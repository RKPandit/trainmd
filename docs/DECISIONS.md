# Design Decisions Log

Per CLAUDE.md: every design decision that deviates from the spec gets a line
here (date, decision, reason). The spec is then updated, not silently bypassed.

| Date | Decision | Rationale | Spec ref |
|------|----------|-----------|----------|
| 2026-09-07 | Docker deferred to M2.2; SageMaker path/env-var conventions (SM_CHANNEL_*, SM_HPS, SM_MODEL_DIR) kept in M2.1 training scripts as CLI-arg fallbacks | M2.1 scope is repo scaffold + reference protocol. Training scripts accept SageMaker env vars but fall back to CLI args for local execution, avoiding Docker complexity while maintaining interface compatibility. The full container contract (spec §2) will be enforced in M2.2. | §2, §11 M2.1 |
| 2026-09-07 | Two-metric visible/hidden split: `metric_visible_val_acc` (agent-visible), `metric_hidden_test_acc` (hidden, recovery oracle) | The recovery oracle (spec §3, §7) must use a held-out test metric that agents never optimize against. Validation accuracy is the agent-visible metric for diagnosis; test accuracy determines recovery success. Tolerance bands (`mean − 2·std`) are computed on the hidden test metric only. | §3, §7 |
| 2026-09-07 | Hidden metric computed only by evaluator on saved checkpoints; workspace never sees test data; data split config separated from training config | `train.py` never loads test data or computes `metric_hidden_test_acc`. The evaluator (`harness/evaluator/evaluate_checkpoint.py`) is the sole code path for the hidden metric. Data-prep config (`data_split.yaml`) is separate from the training config so `config.resolved.yaml` never mentions holdout fractions or split metadata. Hidden data lives in `.hidden_data/` (sibling to `.data/`), not a subdirectory, so a single volume mount of `.data/` cannot leak test files. | §7 |
| 2026-09-07 | Canonical reference environment is Linux x86_64 (CI); macOS runs are development smoke tests only; committed reference snapshots are always CI-generated | Cross-platform training divergence (~0.001 in val_acc mean) between macOS ARM and Linux x86_64 is the same order as seed-to-seed std (~0.0017), so tolerance bands are only valid on the platform that generated them. The reproducibility claim targets the shipped Linux container environment. macOS `make reference` is useful for development smoke tests but its stats.yaml must not be committed. | §3 |
| 2026-09-07 | Frozen dataclasses for operator data types (MutationRecord, Manifest, EvidenceRef, RepairSpecSchema) | Immutability after creation supports spec §7 integrity: ground-truth records cannot be accidentally modified after operator `apply()` returns. Frozen dataclasses serialize cleanly via `dataclasses.asdict()`. | §4, §7 |
| 2026-09-07 | lr_warmup uses absolute LR values (mild=0.1, moderate=0.2, severe=0.5) not multipliers of the reference LR | Absolute values are simpler to reason about and verify. Empirically tuned: lr=0.05 (5x) does not reliably fail tolerance on all seeds; lr=0.1 (10x) is the lowest value that reliably fails across 10 seeds on macOS and 3 seeds on Linux. All strengths produce completed runs with finite metrics (silent-layer invariant). | §4 |
| 2026-09-07 | Admissible repair range capped at [0.001, 0.02] for lr_warmup | Upper bound (0.02) is well below the mildest faulty value (0.1), ensuring "change nothing" is never an admissible repair. Reference value (0.01) is within the range. | §4 |
| 2026-09-07 | build_case symlinks `.data/` into workspace (not copied); writable symlink is an open risk | Matches the Docker volume-mount model where data is mounted read-only. In the current single-process setup, the symlink is writable — an agent could corrupt shared data. Read-only enforcement will be added in M2.2c (Docker container `ro` mounts or a FUSE/bind-mount shim). | §2, §5 |
| 2026-09-07 | Opaque sequential case IDs (case_0001, case_0002, ...); generation params only in hidden-side registry | Readable case IDs like `tabular_adult_lr_warmup_moderate_s42` would announce the diagnosis to the agent. The hidden registry `cases/registry.hidden.yaml` maps opaque IDs to generation parameters for developer use. | §5, §7 |
| 2026-09-07 | Silent-layer operators must produce completed runs (exitcode=0, finite metrics); crash/NaN belongs to execution tier | build_case enforces this at build time with guards that reject cases where the faulty run crashes or produces NaN. Hidden eval seeds [100, 101, 102] never overlap reference seeds [0-9]. | §4 |
| 2026-09-07 | Mutation replay from card.hidden.yaml rather than operator re-instantiation | verify_repair replays mutations by navigating the config dict via `key_path` from `card.hidden.yaml["mutations"]`, then applies the repair patch on top. This is operator-agnostic (no operator import needed at eval time), auditable (the exact key paths and values are recorded), and avoids coupling the evaluator to operator internals. | §7 |
| 2026-09-07 | Integrity hash is a sanity check in v1; physical enforcement via Docker in M2.2c | SHA-256 of verify.yaml is computed before and after each evaluation run. In v1 this detects accidental modification; the evaluator raises RuntimeError on mismatch. True tamper-proofing (read-only bind mounts) requires Docker isolation, deferred to M2.2c. | §7 |
| 2026-09-07 | Results written to `results/<case_id>/` at project root, not in `hidden/` | `hidden/` is immutable ground truth, written once at case-build time and never modified. Evaluation results are a separate artifact class. `results/` is already in .gitignore. | §7 |
| 2026-09-07 | All admissible-range LR values recover for lr_warmup on tabular_adult; recovery axis alone cannot distinguish correct diagnosis from blind in-range guess | Empirical sweep of lr∈{0.001..0.02} on hidden seeds [100,101,102]: all above tolerance 0.843535. lr_warmup is a deliberately easy recovery case. RQ4/RQ5 analysis must rely on operators with non-trivial repair spaces plus the diagnosis/evidence axes. The not_recovered verdict path is tested via artificially elevated tolerance. | §7, §4 |
| 2026-09-07 | Tool layer is pure Python API (no HTTP/gRPC) | Simplest correct thing for v1. Agents call `tools.call("tool_name", **kwargs)` and get back dicts. No network serialization overhead, no server process. Will be wrapped in an HTTP layer when Docker isolation is added. | §6 |
| 2026-09-07 | Path confinement via `resolve()` + `is_relative_to()` only; no string-based name blocking | `Path.resolve()` eliminates `..` and follows symlinks; `is_relative_to(workspace_root)` is the sole confinement check. String checks for names like "hidden" would break legitimate files (e.g. `hidden_layers.txt`) and add a brittle blocklist that resolve() already subsumes. | §6 |
| 2026-09-07 | Evidence matching is greedy bipartite (not optimal assignment) | For each submitted ref, find first unmatched hidden ref that matches. Sufficient for small ref sets in v1 (operators produce 1-3 evidence refs). Optimal assignment (Hungarian algorithm) adds complexity for no practical benefit at this scale. | §8 |
| 2026-09-07 | ~~Operator class mapping is a manual lookup table (`_OPERATOR_CLASS_MAP`)~~ | ~~Maps operator IDs to human-readable classes.~~ Superseded by 2026-09-10 accepted-class set below. | §8 |
| 2026-09-07 | Stub oracle + stub degenerate agents prove scoring discriminates diagnosis quality from blind recovery | Both agents submit valid in-range repairs and recover, but oracle scores 1.0 on identification and evidence while degenerate scores 0.0 on both. `test_scoring_discriminates` validates this invariant. Confirms that the four-axis scoring design separates correct diagnosis from lucky repair. | §8 |
| 2026-09-07 | Versioned provenance schema (v1.0) captures environment, model, usage, scores in one file per trial; partial records flushed before agent starts | Storage is free, reruns are not. Every paid token must be captured even on crash. Schema version allows migration. `index.jsonl` enables DataFrame-level analysis without opening every YAML. | §6, §8 |
| 2026-09-07 | Scoring split by cost: `run_trial` scores 3 free axes (detection, identification, evidence) + safety inline; recovery is a separate explicitly-invoked step (`score_recovery_standalone`) | The paid LLM call and the CPU-bound recovery verification (3 hidden seeds x training) are separate cost centers. The durable checkpoint between them means the paid record is complete the instant the agent returns. Recovery can be run later, repeated, or skipped — it never risks the paid record. | §8 |
| 2026-09-07 | `index.jsonl` uses append-mode open + single-line write + flush; concurrent trial interleaving is an accepted risk (single-process for now) | Append-mode open is atomic on POSIX for writes <= PIPE_BUF. Sufficient for single-process sequential trials. Concurrent trials could interleave partial lines; acceptable because the harness is single-process in v1. Will revisit with file locking if parallel trials are added. | §8 |
| 2026-09-07 | LLMClient is a Protocol with FakeLLMClient for testing; provider clients are separate classes | All agent logic is testable at zero cost via scripted fake responses. Provider coupling is isolated to one file per provider. | §6 |
| 2026-09-07 | LLMAgent receives mutable record via `set_record()` rather than changing Agent Protocol | Avoids breaking the Protocol contract for stub agents. Only LLM agents need incremental usage capture; stubs have zero tokens. Duck-typing via `hasattr` keeps it simple. | §6 |
| 2026-09-07 | AnthropicClient bounded retry: max 2 retries on transient errors only (rate-limit, 5xx, timeout, connection); no retry on auth (401/403) or bad request (400) | Transient errors are recoverable; auth and validation errors are not. 3 attempts total with exponential backoff (1s, 2s) keeps latency bounded. Model-not-found (404) raises ValueError with docs URL to guide user. | §6 |
| 2026-09-07 | Model IDs and prices verified against docs.anthropic.com (Sep 2026); all costs flagged `is_estimate=True` | Claude 4.7+ tokenizer counts ~30% more tokens for the same text, making per-token prices a lower bound on actual cost. `is_estimate` flag prevents unverified cost figures from reaching paper tables. Cache-read prices confirmed individually ($0.10/$0.20/$0.50); null-fallback in `estimate_cost` charges unverified cache at full input rate. | §6, §8 |
| 2026-09-07 | `anthropic` SDK is optional dependency under `[llm]` extra | Keeps the core harness installable without network-dependent SDK. Stub agents, scoring, and all offline tooling work with base deps only. LLM trials require `uv pip install -e '.[llm]'`. | §6 |
| 2026-09-07 | Smoke model default is cheapest current model (Haiku 4.5, $1/$5 per MTok) | Minimizes cost for development iteration. `SMOKE_MODEL` Makefile var is overridable for testing other models. | §6 |
| 2026-09-07 | Evidence ground truth enumerates all fault-relevant pointers (fault-localization convention); matching normalizes to fault granularity | config_key matches on key_path + normalized config artifact (source and resolved config treated as same logical file via `_CONFIG_ARTIFACT_BASENAMES`; refs pointing at non-config artifacts are rejected to prevent unsourced key guesses from getting free credit). metric_window matches on series + interval overlap. Ground truth windows cover the full extent of the fault's observable effect. This is lenient-but-consistent, following the standard fault-localization / RCA benchmark convention: mark everything the fault touches, credit any hit. | §8 |
| 2026-09-07 | Case generation is idempotent — (workload, operator, strength, seed) maps to exactly one case ID | Re-builds refuse by default and require `--force` to regenerate in place, reusing the existing case ID. Prevents silent duplication from inflating sweep results. Registry lookup checks the tuple before allocating a new sequential ID. | §5 |
| 2026-09-07 | Trial record is single source of truth; index.jsonl is a derived view kept in sync on every (re)score; recovery merges into trial record and is idempotent | `update_index(project_root, record)` replaces `append_index` + `update_index_recovery`: reads the full record, derives the index line via `_index_line`, and rewrites in place (or appends if new). Recovery results are named `recovery_<trial_run_id>.yaml` so re-verification overwrites, not duplicates. `score_recovery_standalone` merges the verdict into the trial record's `scores.recovery` field and calls `update_index`. | §6, §8 |
| 2026-09-07 | Automated case validator with WALL/CONSISTENCY/WELL-FORMEDNESS checks; deep mode optional; index-drift and recovery-linkage checks on existing trials | Post-build validation catches isolation breaches, cross-file inconsistencies, and schema gaps without manual review. C7 catches index.jsonl drift vs trial records. C8 catches orphaned recovery files. Both skip cleanly when no trials exist. Deep mode (C6: verify mutations applied in resolved config) is opt-in. Tolerance recomputed from reference stats (not magic constant) with epsilon comparison. | §5, §7, §8 |
| 2026-09-07 | Per-operator evidence review: ground truth enumerates every artifact/series the fault observably corrupts, reviewed once per operator | lr_warmup evidence expanded from 2 refs (config_key + train_loss) to 3 (+ metric_visible_val_acc). A too-high LR corrupts both loss and accuracy curves; omitting val_acc penalized agents that correctly cited it. Pattern: each operator's evidence set is reviewed once after initial live trial to ensure completeness. | §8 |
| 2026-09-09 | Label corruption operator (`silent.label_corruption.v1`): config-flag design with `data.label_noise_fraction` knob; true `data_fix` repairs deferred | Config-flag approach keeps repairs as `config_patch` for now. Config key uses "noise" not "corruption" to avoid W1 isolation false positive (operator ID segment `label_corruption` must not appear in workspace files). Strengths calibrated empirically: mild=0.15, moderate=0.25, severe=0.35 (5% and 10% did not reliably fail tolerance on this workload). Corruption RNG is seed-independent — `hash((data_length, noise_fraction, 0xDEAD_BEEF))` — so evaluator reruns with hidden seeds see the same corrupted label set. Admissible repairs exclude `training.lr`: an LR fix must not recover a data fault (RQ4/RQ5). Empirically verified: train_loss +104% above reference (strongest signal), val_acc −1.9% below reference, both anomalous across all 20 epochs. Oracle repair (fraction=0.0) recovers on all 3 hidden seeds; LR repair rejected with KEY_NOT_ALLOWED. | §4, §8 |
| 2026-09-10 | Identification matches an enumerated accepted-class set per operator; mechanical, no judge. Supersedes `_OPERATOR_CLASS_MAP` | Haiku correctly diagnosed label-corruption but named it `"data_corruption"` while ground truth was the raw operator_id (no `_OPERATOR_CLASS_MAP` entry → silent fallback to unmatchable `"silent.label_corruption.v1"`). Fix: each operator exposes `accepted_classes() → frozenset` of legitimate names. `build_case` writes the set into `card.hidden.yaml`. `score_identification` normalizes (lowercase, collapse separators) and checks membership. Same "enumerate all legitimately-correct answers" convention as evidence matching and config artifact normalization. Guard: if `accepted_classes` is missing from hidden card, `score_identification` returns `correct=False` AND sets `accepted_classes_missing=True` (visible failure, not silent). Validator check F4 catches missing accepted_classes at build/validate time. | §4, §8 |
| 2026-09-10 | Crash operators use `operators/crash/` directory, not `operators/execution/` from spec §1 | `execution` is already the layer field value; same word for directory creates confusion. `crash` parallels `silent` (directory for dynamics-layer operators). | §4 |
| 2026-09-10 | Build guard inverted for execution tier: exitcode=0 REJECTED | Silent operators must complete; crash operators must fail. Guard enforces tier invariant at build time. Same pattern as dynamics guard but inverted condition. | §4, §5 |
| 2026-09-10 | `faulty_value: null` in verify.yaml for crash operators | No checkpoint → no accuracy to record. Null signals validator/scorer that recovery must be judged by completion + tolerance, not by comparing faulty vs tolerance numerically. Validator C5 and F3 updated for tier-awareness. | §7 |
| 2026-09-10 | Recovery for crash = exitcode=0 AND metric >= tolerance | Completing alone is insufficient — a fix that stops the crash but trains badly is NOT recovered. `verify_repair.py` already handles this: non-zero exitcode → metric=None → `not_recovered`. No code changes needed. | §7 |
| 2026-09-10 | Log-based evidence via existing `line_range` kind on `logs/stdout.log` | Crash operators produce evidence in logs (tracebacks), not metric time series. `line_range` kind already existed in `EvidenceRef` and `_match_evidence_ref`. Evidence range [2, 24] empirically determined: covers `[ERROR] Training failed:` through `RuntimeError: mat1 and mat2 shapes cannot be multiplied`. Stable across all strengths and seeds. | §8 |
| 2026-09-10 | `model.input_dim` config override is 1-line backward-compatible hook | `mcfg.get("input_dim", input_dim)` is no-op when key absent. All existing reference runs and cases produce identical results. Verified empirically: clean config with and without the hook produces bitwise-identical training output. | §4 |
| 2026-09-10 | Shape mismatch recovery is binary: only exactly 105 completes; all other in-range values crash | `nn.Linear` requires exact dimension match between weight matrix and input tensor. There is no "completes but trains badly" path for this operator. Admissible range [90, 120] includes correct value (105); all faulty values (1, 10, 50) below range. Negative recovery tested via any non-105 value → crash → `not_recovered`. | §4, §7 |
| 2026-09-10 | `artifact_inventory` omits `ckpt_final.pt` for execution tier | Checkpoint doesn't exist when training crashes. Inventory must match what agents can observe. Validator F5 check enforces tier-appropriate checkpoint presence/absence. `ckpt_final.pt` removed from `_REQUIRED_FILES` (tier-conditional); F5 replaces it. | §5 |
| 2026-09-10 | Agent evidence enum and prompt must enumerate all kinds the scorer accepts | LLM agent schema had `enum: ["config_key", "metric_window"]` — missing `line_range` and `code_span`. Agents hitting crash-tier cases correctly located tracebacks in logs but were forced to improvise fake `metric_window` refs, silently capping evidence F1. Fixed: enum expanded to all four kinds, detail descriptions added, prompt reworded to guide evidence kind by symptom (metric_window for bad curves, line_range for errors/tracebacks) without biasing silent-tier cases. | §6 |
| 2026-09-10 | Resolved config must nest `input_dim` under `model`, not at top level | `train.py` wrote `resolved = {**config, "input_dim": input_dim}`, putting `input_dim` at the top level alongside the nested `model.input_dim`. Agents reading `config.resolved.yaml` cited the top-level path `input_dim`, which didn't match the operator's evidence key_path `model.input_dim`, silently mis-scoring correct diagnoses. Fixed: `input_dim` now written via `resolved["model"]["input_dim"] = input_dim`, consistent with the operator's mutation path, evidence, and repair spec. Regression test added. All three cases rebuilt. | §4 |
